# Call-order audit: `PATH_*` / `STATES_*` / `SEED_*` side effects (D2Game 1.13c vs TS)

Why this exists: several D2Common setters have side effects on each other, so the **order** of the
calls matters, not just the set of calls. Example that cost a whole investigation:
`#10286 PATH_SetTargetPos` clears `pTargetUnit`, so calling it *after* `#10336 PATH_SetTargetUnit`
silently drops the chase target and `D2Common_10226` never stops a chasing monster next to the player
(`p52-paladin-auras` frame 748). Every TS call site of an order-sensitive setter must be listed here
against the original call site.

Conventions: D2Game addresses are 1.13c preferred-base VAs; `#n` is the D2Common ordinal reached
through the D2Game import thunk (resolved with `objdump -p D2Game.dll`); TS links point at
`src/`. Status: **match** (same calls, same order), **fixed** (was wrong, corrected in the commit
named), **equivalent** (different calls, provably identical state), **pending** (original call
site not yet disassembled — do not rely on it).
